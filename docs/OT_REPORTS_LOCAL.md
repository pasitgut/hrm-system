# รายงาน OT PDF

หน้านี้บันทึกการตั้งค่าและกติกาของรายงาน OT ที่หน้า `/reports` แท็บ OT ใช้ข้อมูล OT จริงจากฐานข้อมูลและสร้าง PDF บนเซิร์ฟเวอร์

## เปิดใช้งานในเครื่อง

1. ตั้งค่า `DATABASE_URL` ให้ชี้ไปยังฐานข้อมูลของแอป
2. ติดตั้งแพ็กเกจด้วย `npm install`
3. รัน `npm install` และ `npm run db:migrate`
4. เริ่ม Next.js ด้วย `npm run dev` แล้วเปิด `/reports`

PDF สร้างด้วย PDFMake และฝังฟอนต์ TH Sarabun New จาก `public/THSarabunNew.ttf` และ `public/THSarabunNew-Bold.ttf` จัดหน้า A4 ตามรูปแบบรายงานเดิม: ส่วนหัวแสดงเวลา บริษัท และเลขหน้า, ตารางพื้นสีเทาเข้ม เส้นกริดบาง และระยะขอบ 20 pt ซ้าย/ขวา/ล่าง โดยไม่มีส่วนท้ายหน้า รายงานรายละเอียดแสดงหัวพนักงานและหัวตารางซ้ำเมื่อขึ้นหน้าใหม่ ไม่ต้องติดตั้ง Chromium

## รูปแบบรายงาน OT

| รหัส | เนื้อหา |
| --- | --- |
| `monthly-all` | สรุป OT ประจำเดือนของพนักงาน แยกตามแผนก |
| `monthly-individual` | สรุป OT ประจำเดือนแยกตามพนักงานที่เลือก |
| `monthly-individual-detail` | รายการ OT รายวันประจำเดือน พร้อมยอดรวมต่อพนักงาน |
| `yearly-all` | สรุป OT รายปีของพนักงาน แยกตามแผนก |
| `yearly-all-month-columns` | ตารางต่อเนื่อง 12 เดือน โดยมีคอลัมน์ชื่อเดือนหนึ่งคอลัมน์และแถวเรียงตามเดือน |
| `yearly-all-month-pages` | 12 ส่วนรายเดือน เริ่มหน้าใหม่ในแต่ละเดือน พร้อมสรุปทั้งปีท้ายรายงาน |
| `yearly-individual` | สรุป OT รายปีแยกตามพนักงานที่เลือก |
| `yearly-individual-month-columns` | ตาราง 12 เดือนแยกตามพนักงาน โดยมีคอลัมน์ชื่อเดือนหนึ่งคอลัมน์ |
| `yearly-individual-month-pages` | ส่วนรายเดือนแยกตามพนักงาน พร้อมสรุปปีท้ายส่วนของพนักงานแต่ละคน |
| `yearly-individual-detail` | รายการ OT รายวันต่อเนื่องทั้งปีแยกตามพนักงาน |
| `yearly-individual-month-columns-detail` | รายการ OT รายวันต่อเนื่องทั้งปี พร้อมคอลัมน์เดือน |
| `yearly-individual-month-pages-detail` | รายการ OT แยกหน้าและยอดรวมรายเดือนต่อพนักงาน พร้อมสรุปทั้งปี |

## ขอบเขตและการคำนวณ

- รายงานรวมเฉพาะคำขอ OT สถานะอนุมัติแล้ว โดยกรองตามเวลาเริ่ม OT ในเดือนหรือปีปฏิทินเขตเวลา `Asia/Bangkok` เดือนเริ่มวันที่ 1 และสิ้นสุดวันสุดท้ายของเดือน
- เวลาทำงานคำนวณจากเวลาเริ่มและสิ้นสุดที่บันทึกจริง รวมช่วงข้ามวันตามเวลาที่ผ่านไป ไม่มีการหักเวลาพัก เพราะข้อมูลคำขอไม่มีช่องเวลาพัก
- ประเภทที่บันทึกเป็น `weekday` และ `holiday` แยกเป็นคนละยอด ประเภทว่างหรือค่าอื่นจะแสดงเป็น “ไม่ระบุประเภท” มีคำเตือน และยังรวมอยู่ในยอดรวม เพื่อไม่ให้ชั่วโมงหายไป
- รายงานรวมพนักงานที่ยังทำงานอยู่และพนักงานในประวัติที่เกี่ยวข้องกับคำขอ OT ชื่อแผนกและตำแหน่งอ้างอิงข้อมูลปัจจุบันในระเบียนพนักงาน
- ไม่อ่านหรือแสดงเงินเดือน อัตราค่า OT จำนวนเงิน โครงการ หรือข้อมูลชดเชยที่ไม่มีในคำขอ OT
- เลือกพนักงานได้สูงสุด 100 คนต่อไฟล์ เรียงตามตำแหน่ง ชั่วโมง ชื่อ หรือแผนกได้หลายเงื่อนไขโดยไม่ซ้ำกัน
- รายการพนักงานสำหรับตัวเลือกจำกัด 2,000 รายการ รายงานจำกัด 5,000 พนักงานและคำขอ OT 25,000 รายการต่อไฟล์ หากเกินขีดจำกัด API จะตอบข้อผิดพลาดโดยไม่สร้างไฟล์
- การกำหนดช่วงวันเอง รายงานวันลา และรายงานเบี้ยขยันยังไม่พร้อมใช้งาน

## สิทธิ์และ API

ต้องมี `reports.view` และสิทธิ์ OT อย่างใดอย่างหนึ่งตามขอบเขต: `ot.view_company` หรือ `ot.approve` สำหรับรายงานทั้งบริษัท; `ot.view_self` หรือ `ot.request.self` สำหรับรายงานส่วนตัว ผู้ใช้ที่ดูได้เฉพาะข้อมูลตนเองส่งออกได้เฉพาะรูปแบบรายบุคคลและรหัสพนักงานของตน

- `GET /api/reports/ot/options` ส่งคืนตัวเลือกพนักงานขั้นต่ำที่ผู้ใช้มีสิทธิ์เข้าถึง
- `POST /api/reports/ot/export` รับ JSON ของรูปแบบ ปี เดือน รหัสพนักงาน และเงื่อนไขเรียงลำดับที่เกี่ยวข้อง แล้วส่งคืน `application/pdf`

ตัวอย่าง payload รายเดือน:

```json
{
  "variant": "monthly-individual-detail",
  "year": 2026,
  "month": 10,
  "employeeIds": ["00000000-0000-4000-8000-000000000001"],
  "sortRules": [{ "field": "hours", "direction": "desc" }]
}
```

ทุกคำขอตรวจสิทธิ์และตรวจรูปแบบข้อมูลฝั่งเซิร์ฟเวอร์ ตัวเลือกพนักงานไม่เรียก API รายชื่อพนักงานทั่วไป จึงไม่ต้องมีสิทธิ์ `employees.profile.view` เพิ่ม การส่งออกตอบกลับด้วย `no-store` และชื่อไฟล์ที่สร้างจากรูปแบบกับช่วงเวลา

## ตรวจสอบในเครื่อง

ตรวจชนิดข้อมูลและชุดทดสอบเฉพาะรายงาน:

```powershell
npx tsc --noEmit --incremental false
npx vitest run lib/reports/ot/model.test.ts lib/reports/ot/options.test.ts lib/reports/ot/access.test.ts lib/reports/ot/pdfmake.test.ts app/api/reports/ot/export/route.test.ts app/api/reports/ot/options/route.test.ts
```

สร้าง PDF fixture ครบ 12 รูปแบบและ PDF stress test สำหรับเหตุผลภาษาไทยที่ยาวหลายหน้า:

```powershell
npx tsx --env-file-if-exists=.env scripts/verify-ot-report-fixtures.ts
```

ไฟล์อยู่ใน `output/pdf/ot-report-fixtures/` สคริปต์นี้ใช้ข้อมูลสังเคราะห์ ไม่อ่านหรือเขียนฐานข้อมูล

ตรวจฐานข้อมูลจริงแบบอ่านอย่างเดียวสำหรับเดือนปัจจุบันในกรุงเทพฯ และบันทึก PDF ตัวอย่างไว้ใน `output/pdf/ot-reports/`:

```powershell
npx tsx --env-file-if-exists=.env scripts/verify-ot-report-live.ts
```

สคริปต์นี้บันทึกเฉพาะจำนวนพนักงาน จำนวนคำขอ ลายเซ็น PDF ขนาดไฟล์ และเส้นทางไฟล์ ปิดการเชื่อมต่อเมื่อเสร็จ และใช้คำสั่งอ่านฐานข้อมูลเท่านั้น

## ผลตรวจสอบรูปแบบ PDF

- PDFMake สร้าง fixture ครบ 12 รูปแบบและ 1 stress test รวม 175 หน้า A4; pypdf ตรวจว่าไม่มีหน้าเปล่า และ sentinel `OTEND9F4C` อยู่ใน PDF stress test 7 หน้า
- ตรวจภาพรายงานสรุปรายเดือน รายละเอียดรายปี และหน้าต้น/ท้ายของ stress test ด้วย pypdfium2
- ชุดทดสอบ PDFMake ของ OT ผ่านร่วมกับชุดทดสอบ Leave และ Salary ตามบันทึกในงาน migration; ไม่ได้รัน live database smoke ในรอบนี้
