# Payroll data source

The `/payroll` page calculates a preview directly from employee and request data in PostgreSQL. It no longer needs a salary Excel import. Users with `salary_slips.view` and `employees.compensation.view` can view calculations; `salary_slips.export` also allows the monthly workbook export.

The selected payroll month covers the 26th of the previous month through the 25th of the selected month in `Asia/Bangkok`, matching the existing OT payroll period. Base salary and enabled employee payroll items with unit `period` are included. Only approved OT requests affect pay; pending OT hours and request counts are shown separately. OT pay uses base salary ÷ 30 ÷ employee work hours per day × the employee's weekday or holiday multiplier × approved hours. An approved OT request without a day type blocks export until it is classified. Employees without a base salary or work hours per day also block export. Enabled payroll items with day/hour/time units are shown as unresolved and block export because the current system has no attendance quantity source for those units.

The workbook has a summary sheet with employee and bank details, an itemized income/deduction sheet, and a sheet listing approved leave type, date range, and session. Leave is reference information and is not deducted automatically. Tax, social security, attendance, and proration are not inferred from current records. Configure fixed deductions in the employee payroll profile. Payroll values are recalculated from current employee and request records when viewed or exported; the preview is not a locked or archived pay run.

The previous salary-slip import endpoints and stored imported records remain for compatibility, but `/salary-slips` and `/salary-slips/import` now direct users to `/payroll`. The new payroll export uses the Node.js runtime and creates the `.xlsx` workbook in memory.
