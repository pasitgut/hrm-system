# Spec: การคำนวณเงินเดือนส่วนขยาย (รายการหน่วยวัน/ชั่วโมง และวันลา)

สถานะที่สำรวจ: หน้า `/payroll` (`lib/payroll/`) คำนวณเงินเดือนจากฐานเงินเดือน, รายการประจำหน่วย `งวด (period)`, และ OT ที่อนุมัติแล้วเท่านั้น; รายการประจำที่ตั้งหน่วยเป็น `วัน` / `ชั่วโมง` / `ครั้ง` จะติดสถานะ `unpricedItems` และบล็อกการส่งออก Excel ส่วนวันลาที่อนุมัติแสดงเฉพาะจำนวนคำขอและยังไม่หักเงินอัตโนมัติ (ดู `docs/PAYROLL_DATA.md`)

## เป้าหมาย

กำหนดแนวทางที่ชัดเจนและเชื่อถือได้สำหรับการจัดการรายการค่าตอบแทนตามปริมาณ (วัน/ชั่วโมง/ครั้ง) และการหักเงินจากวันลาในรอบเงินเดือน เพื่อไม่ให้การส่งออก Excel ถูกบล็อกโดยไม่มีทางแก้ไข

## ขั้นตอน prerequisite

1. เจ้าของผลิตภัณฑ์/ฝ่ายบุคคล ยืนยันความต้องการใช้งานของแต่ละส่วน:
   - **รายการหน่วยวัน/ชั่วโมง/ครั้ง** (เช่น เบี้ยขยันรายวัน, ค่าเดินทางรายครั้ง, หักมาสายรายชั่วโมง): ต้องการกรอกปริมาณรายงวดในหน้า `/payroll` หรือดึงจากระบบลงเวลาภายนอก หรือจำกัดให้ตั้งค่าเฉพาะหน่วย `งวด` ในโปรไฟล์พนักงาน
   - **การหักเงินจากวันลา** (เช่น ลาไม่รับค่าจ้าง / ลากิจเกินโควตา): ต้องการให้ระบบคำนวณหักอัตโนมัติจากประเภทการลาที่กำหนด หรือคงไว้เป็นข้อมูลอ้างอิงให้ฝ่ายบัญชีตรวจเอง
2. หากต้องกรอกปริมาณรายงวดหรือเก็บผลคำนวณย้อนหลัง ต้องออกแบบ schema `payroll_adjustments` หรือ `payroll_runs` พร้อม migration และ audit log (ใครแก้ เมื่อไร ค่าเดิม/ค่าใหม่)

## ข้อกำหนด (หลังยืนยันแนวทาง)

- **กรณีรองรับปริมาณรายงวด:**
  - เพิ่มช่องบันทึกจำนวนวัน/ชั่วโมง/ครั้งต่อพนักงานต่องวดใน `/payroll` และเก็บลงฐานข้อมูลพร้อมตรวจสอบสิทธิ์ `employees.compensation.manage`
  - คำนวณยอดเข้าสู่ `incomeTotal` / `deductionTotal` / `netPay` และแสดงรายละเอียดในตารางรวมถึงชีต `Itemized` ของไฟล์ Excel
- **กรณีรองรับการหักวันลาอัตโนมัติ:**
  - ระบุ flag ใน `leave_types` (เช่น `is_paid`) ให้ชัดเจนว่าประเภทการลาใดหักเงินและใช้ฐานหารวันแบบใด (เช่น ฐาน 30 วันตามสูตร OT)
  - ตัดวันลาที่คาบเกี่ยวข้ามเดือนให้คิดเฉพาะวันภายในงวดที่คำนวณ (ตาม timezone `Asia/Bangkok`)
- **กรณีไม่รองรับหน่วยวัน/ชั่วโมงในระบบ:**
  - ปรับ validation ในโปรไฟล์พนักงาน (`EmployeeModule.jsx` และ API) หรือแจ้งเตือนตั้งแต่ตอนตั้งค่า เพื่อไม่ให้ตั้งหน่วยที่ส่งออกเงินเดือนไม่ได้โดยไม่รู้ตัว

## เกณฑ์ตรวจรับ

- มีข้อสรุปนโยบายเป็นลายลักษณ์อักษรก่อนเปลี่ยนสูตรคำนวณหรือ schema
- ยอดบนหน้า `/payroll` และไฟล์ Excel ที่ส่งออกตรงกันทุกคอลัมน์
- มี unit/API tests ครอบคลุมรายการหน่วย `งวด`, หน่วยตามปริมาณ, วันลาครึ่งวัน/ข้ามเดือน และสิทธิ์การแก้ไข
