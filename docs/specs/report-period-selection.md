# Spec: ตัวเลือกงวดรายงาน

สถานะที่สำรวจ: หน้า `/reports` รองรับรายเดือนและรายปีอยู่แล้ว และมีตัวเลือก “กำหนดเอง” ที่ยังส่งออกรายงานไม่ได้

## เป้าหมาย

ให้ผู้ใช้เลือกรายงานได้ 3 รูปแบบ: รายเดือน, รายปี และช่วงงวดกำหนดเอง โดยช่วงงวดกำหนดเองเลือกเดือน/ปีเริ่มต้นและเดือน/ปีสิ้นสุด ไม่เลือกวัน

## ข้อกำหนด

- รองรับงวดทั้ง 3 รูปแบบสำหรับรายงาน OT และวันลาที่เปิดใช้งาน:
  - รายเดือน: เลือกปีและเดือน.
  - รายปี: เลือกปี.
  - กำหนดเอง: เลือกเดือน/ปีเริ่มต้นและเดือน/ปีสิ้นสุด.
- ช่วงกำหนดเองเป็นช่วงเดือนเต็มแบบ inclusive ตั้งแต่วันแรกของเดือนเริ่มต้นถึงวันสุดท้ายของเดือนสิ้นสุดตาม `Asia/Bangkok`; ไม่มีช่องเลือกวัน.
- OT ใช้กติกาปัจจุบัน: รวมรายการที่เวลาเริ่มอยู่ในช่วงที่เลือก และคำนวณระยะเวลาของรายการตาม start/end ที่บันทึก แม้รายการจะสิ้นสุดหลังขอบช่วง.
- วันลารวมคำขอที่ทับซ้อนกับช่วงที่เลือก และตัดวัน/ครึ่งวันให้เหลือเฉพาะส่วนที่อยู่ในช่วงรายงาน.
- ตรวจว่าค่าเดือนอยู่ระหว่าง 1–12, ปีถูกต้อง, กรอกงวดเริ่มต้นและสิ้นสุดครบ และงวดเริ่มต้นไม่อยู่หลังงวดสิ้นสุด ทั้งใน UI และ API.
- คงตัวเลือก “กำหนดเอง” ไว้ใน UI; แสดง picker เดือน/ปีเริ่มต้นและเดือน/ปีสิ้นสุดเมื่อเลือกโหมดนี้.
- เพิ่ม API contract/query logic สำหรับช่วงงวดกำหนดเอง โดยใช้ขอบเขตเดือนเต็ม; จำกัด maximum range/จำนวนรายการตามข้อจำกัดฐานข้อมูลและ runtime และแสดง error เมื่อเกินขีดจำกัด.
- API ตรวจสิทธิ์เดิมทุก request; ผู้ใช้ self-only ส่งออกรายงานได้เฉพาะข้อมูลตนเอง.
- ขอบเขตรายเดือนเดี่ยวคือวันแรกถึงวันสุดท้ายของเดือน; รายปีคือ 1 มกราคมถึง 31 ธันวาคม.
- สรุปการตั้งค่า, ชื่อไฟล์ และหัวรายงาน PDF ต้องแสดงงวดเริ่มต้น–สิ้นสุดให้ตรงกับช่วงที่เลือก.

## เกณฑ์ตรวจรับ

- UI มีตัวเลือกครบทั้งรายเดือน, รายปี และ “กำหนดเอง”; โหมดกำหนดเองให้เลือกเดือน/ปีเริ่มต้นและสิ้นสุดโดยไม่มี date picker รายวัน.
- รายงาน OT และวันลาสร้าง PDF ได้ครบทั้งสามรูปแบบ.
- ช่วงกำหนดเองรวมทั้งเดือนเริ่มต้นและเดือนสิ้นสุด; ตรวจกรณีงวดเดียว, ข้ามเดือน, ข้ามปี, ไม่มีข้อมูล และขอบเขตสูงสุด.
- API ปฏิเสธเดือน/ปีผิดรูปแบบ, งวดไม่ครบ, ช่วงกลับด้าน, ช่วงเกินขีดจำกัด และผู้ไม่มีสิทธิ์.
- ขอบเขต query ใช้ `Asia/Bangkok`; สรุปบนหน้าจอ, ชื่อไฟล์ และหัว PDF แสดงช่วงงวดที่ตรงกัน.
- มี targeted UI/API tests และ PDF fixtures สำหรับกรณีข้างต้น.

## การตัดสินใจที่ต้องยืนยัน

- กำหนด maximum จำนวนเดือนต่อรายงานและ record limit ตามข้อจำกัดฐานข้อมูล/runtime ก่อนเปิดใช้; API ต้องปฏิเสธช่วงที่เกิน limit อย่างปลอดภัย.
