# Spec: รายงานเบี้ยขยัน

สถานะที่สำรวจ: หน้า Reports แสดงตัวเลือก “เบี้ยขยัน” แต่ปิดการส่งออกและยังไม่พบ API รายงานเบี้ยขยันที่ใช้งานจริง

## เป้าหมาย

ให้ผู้มีสิทธิ์ตรวจสอบและส่งออกรายงานเบี้ยขยันจากแหล่งข้อมูลที่องค์กรรับรอง โดยไม่สร้างยอดจากการอนุมานที่ไม่มีข้อกำหนดรองรับ

## ขั้นตอน prerequisite

1. สำรวจ schema, import workflow และข้อมูล payroll ที่มีอยู่ เพื่อระบุ source of truth ของยอดเบี้ยขยัน.
2. เจ้าของผลิตภัณฑ์/Payroll ยืนยันแหล่งข้อมูล, รอบงวด, สูตรหรือวิธีบันทึกยอด, การแก้ไขย้อนหลัง และผู้รับผิดชอบรับรองยอด.
3. หากไม่มีข้อมูลยอดรายงวดที่เชื่อถือได้ ให้เสนอ schema/import workflow แยกเป็นงานพร้อม migration, audit history และ recovery plan; ห้ามเริ่มคำนวณจากข้อมูลอื่นโดยสมมติ.
4. ยืนยัน permission model. อย่างน้อยต้องตรวจสิทธิ์ฝั่ง server, จำกัด self-only ให้ข้อมูลตนเอง และไม่เปิดเผยค่าตอบแทนแก่ผู้ไม่มีสิทธิ์.

## ข้อกำหนดหลังยืนยัน source of truth

- รองรับเฉพาะรอบรายงานและรูปแบบ (รวม/รายบุคคล) ที่เจ้าของผลิตภัณฑ์อนุมัติ.
- แสดงงวด, พนักงาน, ยอดและสถานะข้อมูลที่มาจาก source of truth; ยอดต้อง trace กลับไปยังรายการต้นทางได้.
- กำหนดพฤติกรรมของข้อมูลว่าง, ซ้ำ, แก้ไข/แทนที่, พนักงานพ้นสภาพ และงวดที่ข้อมูลไม่ครบ.
- สร้าง PDF ภาษาไทยด้วยรูปแบบร่วมของ Reports; แสดงขอบเขตงวดและวันที่สร้าง.
- API validate input, ตรวจสิทธิ์และ employee scope ทุก request และตอบ `no-store`.
- เปิดใช้งานปุ่มบน UI เมื่อ API, source of truth และ permission พร้อมเท่านั้น; หากยังไม่พร้อมให้แสดงสาเหตุชัดเจน.

## เกณฑ์ตรวจรับ

- มีเอกสารรับรอง source of truth และกติกายอดก่อน merge implementation.
- ทดสอบยอดจาก fixtures ที่ครอบคลุมข้อมูลครบ/ว่าง/ซ้ำ/แก้ไข และผู้พ้นสภาพ.
- PDF ยอดรวมตรงกับข้อมูลต้นทางและเปิดอ่านภาษาไทยได้.
- API ปฏิเสธผู้ไม่มีสิทธิ์และการขอข้อมูลพนักงานอื่น; ไม่มีข้อมูลค่าตอบแทนรั่วใน response ที่ไม่เกี่ยวข้อง.
- หากต้องเพิ่ม schema/import มี migration, audit trail, backup/rollback plan และ targeted tests.
