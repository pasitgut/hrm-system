# Spec: นโยบายข้อมูลและการคำนวณรายงาน

สถานะที่สำรวจ: OT report ใช้ข้อมูลเวลาเริ่ม/สิ้นสุดและข้อมูลพนักงานปัจจุบัน; schema ปัจจุบันไม่มีข้อมูลพักและไม่มี historical department/position snapshot

## การตัดสินใจที่ต้องยืนยัน

### เวลาพัก OT

- ยืนยันว่ารายงานต้องหักเวลาพักหรือไม่.
- ปัจจุบันระบบไม่มีช่องเก็บช่วงพัก จึงหักเวลาพักแบบถูกต้องไม่ได้.
- หากต้องหัก ให้กำหนดแหล่งข้อมูล (พักมาตรฐานหรือพักต่อคำขอ), วิธีกรอก, การแก้ไขย้อนหลัง, timezone, validation และ audit history ก่อนเพิ่ม schema/API.
- หากไม่หัก ให้แสดงชั่วโมงตาม `endAt - startAt` และระบุชัดในคู่มือรายงาน.

### แผนก/ตำแหน่งย้อนหลัง

- ยืนยันว่ารายงานย้อนหลังต้องใช้แผนก/ตำแหน่ง ณ วันที่ทำรายการ หรือใช้ค่าปัจจุบัน.
- ปัจจุบันระบบใช้ข้อมูล employee master ปัจจุบัน; การแสดง historical value ต้องเพิ่ม snapshot/history data และกำหนด behavior สำหรับข้อมูลเก่าที่ไม่มี snapshot.

## ข้อกำหนดร่วม

- ห้ามคำนวณยอดย้อนหลังด้วยข้อมูลปัจจุบันโดยไม่แจ้งข้อจำกัด.
- หากตัดสินใจเปลี่ยน schema ต้องเพิ่ม migration แบบไม่ทำลายข้อมูล, กำหนด backfill/unknown behavior, audit trail และ rollback plan.
- เอกสารรายงานและ PDF ต้องระบุวิธีคิด/ข้อจำกัดที่กระทบการตีความยอด.

## เกณฑ์ตรวจรับ

- มีข้อสรุปเป็นลายลักษณ์อักษรจากเจ้าของผลิตภัณฑ์ก่อนเปลี่ยนสูตรหรือ schema.
- Tests ครอบคลุมค่าพัก/ข้อมูล snapshot/ข้อมูลเดิมที่ไม่มี snapshot ตามกติกาที่อนุมัติ.
- ผลรวมใน PDF/API ตรงกับกติกาที่อนุมัติและตรวจสอบย้อนกลับได้.
