# Spec: ฟอร์มสร้างรายการติดตามงานจาก UI (`/work-tracking`)

สถานะที่สำรวจ: ระบบมี endpoint `POST /api/work` (`app/api/work/route.ts`) และสิทธิ์ `work.create` (`lib/auth/permissions.ts`) รองรับการสร้างรายการติดตามงานลงตาราง `work_tracking_records` อยู่แล้ว แต่หน้า `components/hrm/work-tracking/WorkOverviewPage.jsx` ยังไม่มีปุ่มหรือฟอร์มสำหรับสร้างรายการใหม่

## เป้าหมาย

ตัดสินใจและทำให้ UI กับ API ของโมดูลติดตามงานสอดคล้องกัน — ไม่ว่าจะเป็นการเพิ่มฟอร์มสร้างงานบนหน้า `/work-tracking` สำหรับผู้มีสิทธิ์ `work.create` หรือการปิด/ถอดสิทธิ์ที่ไม่ใช้

## การตัดสินใจที่ต้องยืนยัน

- เจ้าของผลิตภัณฑ์ยืนยันว่าผู้ใช้จำเป็นต้องสร้างรายการติดตามงานเองจากหน้าเว็บ HRM หรือไม่ (นอกเหนือจากรายการที่ดึงมาจาก API Checker และ LINE Bot)
  - **ทางเลือก A (เปิดใช้งาน):** เพิ่มปุ่มและ dialog สร้างรายการใหม่ใน `/work-tracking`
  - **ทางเลือก B (ไม่ใช้งาน):** คงหน้าเว็บแบบ read + update sub-status เท่านั้น และซ่อน/ถอดสิทธิ์ `work.create` ออกจากหน้าตั้งค่าสิทธิ์ผู้ใช้เพื่อไม่ให้ผู้ดูแลระบบสับสน

## ข้อกำหนด (กรณีเลือกทางเลือก A)

- แสดงปุ่ม *"เพิ่มรายการงาน"* ใน `PageHeader` ของ `WorkOverviewPage.jsx` เฉพาะบัญชีที่มีสิทธิ์ `work.create`
- ใช้ `HrmDialog` พร้อมฟิลด์ที่ตรงกับ validation ของ `POST /api/work`:
  - วันที่ (`date`, ใช้ `DatePickerField`)
  - บ้านเลขที่ (`houseNo`, required)
  - รอบงาน (`round`, required)
  - รายละเอียดงาน (`detail`, required)
- แสดง validation error จาก client และ server อย่างชัดเจน, รีเฟรชรายการอัตโนมัติเมื่อสร้างสำเร็จ และแสดงสถานะแจ้งเตือน (`role="status"`)
- คงพฤติกรรม merge ระหว่างข้อมูลจาก API Checker และ `work_tracking_records` ใน `GET /api/work`

## เกณฑ์ตรวจรับ

- **ทางเลือก A:** ผู้มีสิทธิ์ `work.create` สร้างรายการใหม่จาก UI ได้, รายการแสดงในตารางและปรับสถานะงานย่อยต่อได้, ผู้ไม่มีสิทธิ์ไม่เห็นปุ่มและถูกปฏิเสธ `403` ที่ API
- **ทางเลือก B:** ไม่มีสิทธิ์ `work.create` ค้างให้เลือกในหน้าตั้งค่าสิทธิ์โดยไม่มีฟีเจอร์รองรับ
- มี component test และ API test ยืนยันตามทางเลือกที่เลือก
